숫자와 상태 읽기

0은 확인한 범위에서 없음, —는 알 수 없음, ≥는 최소 확인 수입니다. 예를 들어 ≥20은 최소 20개를 확인했지만 전체가 더 많을 수 있다는 뜻입니다. 분모가 붙은 수는 해당 검사 대상에 대한 비율입니다.

자료 수집 · 검색 포함

모은 자료와 그중 현재 과제 검색 목록에 들어 있는 자료를 같은 막대에서 봅니다. 수집 날짜별로 현재 검색 포함 여부를 보여주며, 처리 완료 날짜별 작업량은 아닙니다.

예: 모은 자료 10개 중 검색에 포함된 같은 본문 버전 6개.

사선: 모은 수는 알지만 검색 포함 수를 계산할 기록이 부족함.

표시정확한 뜻판단·다음 행동

검색에 포함 · 채움같은 자료 ID와 본문 버전이 현재 조회 과제의 검색 DB에 연결된 수. 과제 간 같은 자료는 한 번만 셈.검색 후보에 들어 있음. 실제 질문에서 검색되거나 답변에 인용됐다는 뜻은 아님. 댓글·첨부 전체의 완료도 별도.

포함 여부 모름 · 사선자료별 식별 정보나 처리 기록의 연결이 부족하거나 검색 목록 조회가 안 됨.패널 아래 이유 확인. 조회 실패면 다시 읽기, 집계 연결 부족이면 표시 기능의 연결 보완. 무조건 재수집·재처리하지 않음.

검색용 자료 처리 · RAG 처리

전체 개요에서 실제 연결까지

RAG 처리 메뉴는 전체 과제 개요로 시작합니다. 원천별 문서 구성, 과제별 저장 상태와 확인할 항목을 한 화면에서 비교합니다. 공통 RAG의 별도 연결 정보가 없으면 이를 표시하며, 과제 전체 집계를 공통 저장소라고 부르지 않습니다.

과제를 선택하면 실제 DB 연결 그래프를 볼 수 있습니다. 문서 범위를 선택하면 해당 문서의 연결로 좁혀집니다. 노드를 누르면 옆에 연결된 항목과 관계 방향이 표시되고, 이웃 항목을 눌러 이동할 수 있습니다. 그래프는 끌어서 이동하고 확대·축소하거나 전체 맞춤을 사용할 수 있습니다.

원천→과제 구성은 저장 문서의 집계이며 개별 DB 관계와 다릅니다. 상세 그래프의 연결선은 실제 Neo4j 관계입니다. 최대 80개 노드·160개 관계를 보여주는 제한된 범위이므로 화면에 없는 항목이나 선을 누락·고장으로 판단하지 않습니다. 실제 질문에서 따라간 검색 경로도 아닙니다. 원문과 벡터 값은 그래프로 가져오지 않습니다.

어두운 테마·밝은 테마는 운영 화면과 함께 바뀝니다. 전체 범위를 다시 비교하려면 전체 과제 개요로 돌아가기를 누릅니다.

RAG는 질문과 관련된 자료를 찾아 AI 답변에 활용하는 방식입니다. 이 화면은 자료 준비와 검색 DB 저장 상태를 보여줍니다. 답변 품질 점수는 아닙니다.

용어뜻·단위확인할 점
전처리 완료 문서저장 기록에서 검색용 준비가 끝난 문서 수.DB 저장 완료 수와 다름. 아래 검색 DB 수와 함께 확인.
검색 조각(청크)긴 문서를 검색하기 쉬운 본문 조각으로 나눈 것. 수치는 DB에 저장된 조각 수.한 문서가 여러 조각이 되므로 문서 수와 같지 않음.
벡터·임베딩본문의 의미를 숫자 배열로 바꾸는 작업을 임베딩, 그 결과를 벡터라고 함.벡터 포함 청크는 벡터 속성이 있는 조각 수. 의미 정확도·검색 성공은 별도 확인.
검색 DB 저장 일치선택된 처리 버전과 DB의 처리 버전·청크 수가 같고 필요한 벡터 수가 맞는 과제 수 / 조회 과제 수.전체 수집 자료의 처리율이 아님. 불일치면 과제별 처리 이력 확인.
처리 버전한 번의 처리 결과를 구분하는 ID. 이전 화면의 ‘판본’.파일에 저장한 버전과 DB에 저장한 버전을 구분. 이전 버전이 있다고 오류는 아님.
벡터 검색 인덱스비슷한 의미의 벡터를 찾는 DB 검색 구조. ONLINE은 사용할 수 있는 상태, POPULATING은 만드는 중.색인이 준비돼도 모든 질문의 정답을 보장하지 않음. 차원은 벡터 길이이며 문서 수가 아님.
동시 저장 방지 잠금같은 과제에 동시에 저장하지 못하게 하는 잠금 수.0보다 크다고 곧바로 오류는 아님. 장시간 남으면 실행 상태와 소유자 확인 후 조치.
최근 실행에서 저장 확인마지막 실행이 DB 수량을 다시 읽어 확인한 문서 수.현재 전체 문서 수·오늘 새로 처리한 수와 다름.
최근 실행의 대기·실패마지막 실행의 대상 중 대기·실패로 기록된 수.전체 수집 잔량이 아님. 처리 이력에서 해당 항목과 사유 확인.
재처리 목록대기·실패·제외 사유가 남은 재시도 장부의 항목 수.자동 재시도가 허용되는지는 항목별 정책에 따라 다름.
전처리 실패 / 거부처리 시도 실패 / 조건을 충족하지 못해 준비를 허용하지 않음.처리 기록에서 원인을 확인하고 실패 해결 또는 대상 조건 조정. 삭제 대상이라는 뜻은 아님.

품질 점검과 ‘정크’

성격이 다른 수치를 한데 묶어 ‘정크’라고 부르지 않습니다. 처리 당시 제외한 데이터와 지금 DB에서 확인할 데이터를 구분합니다.

표시뜻조치 기준
중복 ID처리 중 같은 ID가 반복돼 제외한 횟수.현재 DB의 중복 개수로 해석하지 않음. 반복 증가 시 추출 결과 점검.
본문·청크 불일치처리 당시 본문·조각 정보가 맞지 않아 제외된 조각.원문과 추출 기록을 확인. 원본 파일 손상으로 단정하지 않음.
출처 청크 없는 개체인물·사물 등 추출 개체의 출처 조각을 찾지 못해 제외한 수.출처 연결을 점검. 저장된 검색 DB 전체의 출처 누락 수는 아님.
제외된 관계연결 양끝의 개체가 없거나 관계 형식이 맞지 않아 제외한 수.해당 처리 결과와 관계 형식 확인. 이 숫자를 삭제할 관계 수로 쓰지 않음.
저장 미완료 표시 노드DB 저장 작업의 임시 표시가 아직 남은 데이터 항목.진행 중 작업인지, 중단 뒤 남았는지 먼저 확인. 자동 삭제하지 않음.
과제 정보 없는 노드DB에 과제 식별 정보가 없는 데이터 항목. 저장 잠금 항목은 제외.출처·생성 경로를 확인한 뒤 처리 방법 결정.

보유량 추세는 시간·날짜별 마지막 확인값입니다. 반복 검사한 수를 신규 처리량으로 더하지 않습니다. 전 과제 기록이 없는 구간은 선이 끊어집니다. 품질 점검 수치의 과거 기록이 없으면 추세를 만들지 않습니다.

RAG 처리 메뉴의 자료별 표는 저장된 처리 기록, 상단 수치는 현재 DB 조회입니다. ‘변경 없음’은 최신 실행에서 새 변경이 없었다는 뜻이며, 실패와 다릅니다. 과제 코드 뒤에는 확인 가능한 과제명을 붙이며 명칭을 읽지 못하면 임의로 만들지 않습니다.

구조·진단 · 시스템 연결도

현재 조치가 필요한 항목에는 원인, 영향, 다음 조치를 표시합니다. 정상적인 순차 처리와 현재 실행을 막지 않는 과거 실패는 현재 장애 수에 합산하지 않습니다.

  • 연결: 서버에 닿거나 API 응답을 받았는지. 인터넷 보안 연결(TLS)만 확인되면 계정 인증·자료 접근은 아직 모릅니다.
  • 수집: 원천 자료를 가져오는 실행 결과. 모든 최신 자료가 빠짐없이 모였다는 보장은 별도 검사가 필요합니다.
  • 보관: 가져온 파일의 식별 정보·내용이 저장 기록과 맞는지. 재해 복구용 백업과 다릅니다.
  • 표본: 일부 파일만 검사함. 표본 통과를 전체 통과로 읽지 않습니다.
  • 검사 결과 다시 읽기: 현재 사용할 수 있는 검사 결과를 다시 조회합니다. 복구 실행이 아닙니다.

실선은 등록된 연결, 점선은 코드에 정의된 연결, 가는 점선은 제어·감시 관계입니다. 선이 있다는 것은 실제 전송 성공을 뜻하지 않으며, 선이 없는 것은 연결 정보가 없다는 뜻일 수 있습니다. 연결도에서 네모는 서비스나 저장소, 상세 검색에서 노드는 데이터 항목, 엣지는 항목 사이 관계입니다.

  • 남은 한도: 계정·모델 묶음별 사용할 수 있는 비율. 막대가 길수록 많이 남음. 남은 토큰 개수는 아닙니다.
  • 5시간·주간: 제공자가 정한 한도 적용 기간. 제공자별·기간별 비율을 더하지 않습니다.
  • 초기화: 해당 한도가 갱신될 예정 시각. 예정 시각이 지났어도 새 조회 없이 100%로 표시하지 않습니다.
  • Antigravity 공유: 표시된 모델 묶음이 함께 쓰는 한도. Gemini 개별 모델마다 독립 한도가 있다는 뜻은 아닙니다.
  • 토큰: 모델이 읽고 생성한 텍스트의 계산 단위. 비용·요금으로 바로 바꾸지 않습니다.
  • 요청·회차: 사용 기록의 호출 또는 대화 회수. 토큰을 측정하지 않는 기록은 요청 수로 따로 보여줍니다.
  • 토큰 미측정: 사용은 기록됐지만 토큰 수를 알 수 없음. 0토큰이 아닙니다.
  • 작업별 귀속: 어떤 작업에서 사용했는지 연결하는 것. 작업 ID 연결이 없으면 모델별 값을 임의 배분하지 않습니다.

사용 추이의 모델/제공자·기간 선택과 아래 작업 이력의 기간 집계는 각각의 표시 범위를 따릅니다. 부분 기록, 오늘 집계 중, 입력·출력·캐시 등 세부 집계 조건은 차트의 집계 범위를 확인합니다.

데이터 공간 · 자료 검색 · 기억·맥락

넓은 화면은 남는 폭을 목록과 상세에 나누어 씁니다. 파일이나 검색 결과를 선택하면 목록 옆에서 내용을 비교할 수 있고, 좁은 화면에서는 상세가 아래 또는 겹친 패널로 표시됩니다.

데이터 공간에서 과제를 선택한 뒤 폴더를 펼치고 파일을 누르면 옆에서 미리 봅니다. ‘별도 창’으로 열 수도 있습니다. 크기는 파일 크기이며 하위 폴더 합계는 제외합니다. 허용된 범위의 파일만 표시하므로 목록이 비어 있다는 것이 저장소 전체가 비었다는 뜻은 아닙니다.

자료 검색은 선택 과제 DB에서 단어로 관련 본문을 찾습니다. AI 답변 생성이나 새 임베딩을 호출하지 않습니다. 한 검색 묶음에서 최대 6회, 결과는 최대 12개입니다. ‘새 검색 묶음 시작’으로 묶음을 새로 시작합니다. 결과의 출처·문서·청크를 보면 어떤 자료가 반환됐는지 알 수 있습니다. 검색 점수는 정답 확률이 아니며 결과가 없다고 DB 전체에 자료가 없는 것은 아닙니다.

기억·맥락은 과제의 해당 저장 공간을 보여줍니다. 맥락은 작업이나 질문에 참고하는 정보입니다. 단기·장기·추론 기억의 생성·활성 여부는 실제 기록이 연결된 경우에만 판단할 수 있습니다. 폴더가 있다는 것만으로 기억 기능이 작동 중이라고 표시하지 않습니다.
