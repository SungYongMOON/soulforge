## b. 무엇을 바꾸는가 — 착수 순서에 영향을 주는 결정 8개

1. **결속 계약 v0.1(EXT-35·38·39)**: `RECORDED`는 접수전용이다. claim·모델 호출·원문 접근은 서버가 인증 주체의
   과제 권한과 유일한 업무 결속을 확인하고 claim 직전 재검사한 뒤에만 연다. 증명하지 못하면 미매핑 후보로만
   기록한다. 커밋 1은 자유 입력을 비활성화하고 닫힌 스키마·서버 정규화 멱등·Origin/CSRF 검사를 넣는다. 접수
   상태는 job·attempt·후보별 영수증만 투영한다. 두 명세의 "착수 가능 = 아니오"를 받아들여 **공유 계약과 반례
   fixture를 먼저 닫고(안 A) 기능 OFF 순수 모듈만 병행**한다.
2. **계약 v1 §2·§5(EXT-44·49·50·51)**: `task:<stage>:<artifact>`는 범위가 결속된 기대 항목의 로컬키다. 실제
   Task·WorkPackage·산출물 revision·수행 episode는 Rune의 권한 아래 관계로 분리하고, 유일성을 증명하지 못하는
   조인은 미매핑으로 남긴다(안 A). Rune 커밋 2의 범위는 식별·관계·필드·상태 정합과 합성 반례 검증까지로 줄이고,
   `state`(업무 증거)와 `procedure_state`(READY / WORKFLOW_GAP)를 분리한다. 불변식 집행·파츠 사전·projection
   writer는 그 뒤다.
3. **불변식 = 결과·증거 조건(EXT-45·46)**: "재고조사 Step 완료"가 아니라 "발주 전 유효한 재고·할당·부족분 판단과
   승인 근거"처럼 승인된 적용 범위의 증거 조건으로 다시 쓴다. 형상-시험 결속 · 실물/외부 행동 승인 · 부적합
   처분 · 보관 검증 네 후보를 추가하되, Domain owner·적용성이 승인되기 전에는 표시만 하고 차단 권한을 주지 않는다.
4. **소나 인텔(EXT-52~56)**: 종합 순위는 시간 분리 backtest 전까지 보류하고 8개 관측 프로필만 보인다. 군집은
   기준 구현 대조 뒤에 켠다. 수집기는 공식 한도(KIPRIS 월 1,000회, EPO GMT 주간 4GB + 동적 제한, OpenAlex 일일
   예산)와 재배포 범위가 결속되기 전까지 OFF다. 순서는 기존 Goal #1 화면의 읽기 패널 → 수집 계약 → 제한 분석 →
   상세 화면 → 승인된 특허 → 검증 후 군집으로 통일한다.
5. **UX(EXT-57~62)**: S2 전에 "읽기·탐색 vs 요청·실행" 경계를 한 문장으로 고정하고 새 탭·drawer·import 하위까지
   같은 시험에 넣는다. S1b로 light 팔레트 대비와 도형 어휘의 축 분리를 고친다. 그룹 표시(§11)는 (d) 시스템
   토폴로지에만 적용하고 건강 순위를 기존 코드와 맞추며, 최악값은 관측 최악값 + 상태별 개수 + 관측/전체 +
   범위·시각으로만 보인다. 접기는 가역이고 요약 간선은 방향·종류·개수·원 ID를 보존한다.
6. **BIND09 면제 제거(CE-11·15)**: 런북의 "미충족이어도 합성 1회 면제" 선택지를 지운다. BIND09는 승인 주체
   신원·권한 분리·sender 재검증 증거로만 닫고, 그 전에는 합성 자료라도 외부 route를 켜지 않는다. 5분
   체크리스트는 선행 검증이 끝난 묶음의 최종 확인표로만 쓴다.
7. **사이클 2호 설계 순서(CE-16~18)**: 실제 HTTP 호출보다 먼저 sender 최종 재검증과 M07 durable 소비 경계를
   설계·검증한다. 응답은 비신뢰 데이터로 격리해 크기·형식·토큰 결속을 CODE로 검증한 뒤 literal-safe 복원한다.
   M10은 제출 식별자 + scope + revision + bytes로 멱등을 정하고 durable 저장 뒤에만 ACK한다. 패키지의 "집게
   4311 = ingress"는 오기였다. 집게(Tongs, 4311)는 봇·팀원이 드나드는 유일한 문(MCP)이고 ingress binding은 Owner가 확정한다.
8. **열쇠 4 = 권한 묶음 4(CE-19)**: 신뢰점·서명 / provider 자격·route / ERP bearer / ingress 제출. 배치 권한과 사용
   권한을 분리하며, 봇 실행 계정은 서명·신뢰 설정 변경·타 과제 접근·수락 권한을 갖지 않는다. 단일 호스트
   파일럿에서는 OS principal·ACL 분리를 Owner 결정 항목으로 올린다.
