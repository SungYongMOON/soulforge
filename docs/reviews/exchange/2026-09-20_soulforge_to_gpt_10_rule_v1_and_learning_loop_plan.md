## 2. 판정 규칙 v1 (모듈 `voice_attribution_policy` 교체)

검사 순서(회신 08 §2 + 09 CE-26):
1. 입력·판본 유효(카드 run이 현재 전사를 가리키는지) → 아니면 `stale`(재생성 대상, skip 아님)
2. 같은 구간의 명시적 사람 정정·철회가 있으면 그것을 유지(AI는 덮어쓰지 않음)
3. 업무성: `project_work`/`team_operations`만 귀속 대상. `unreadable`·형식 오류는 skip이 아니라 `candidate`+복구 표시. `mixed`는 분할 검토 대상(현재는 skip).
4. 예외 우선: 서로 다른 strong 둘(같은 사건) / 등록된 과제와 맞지 않는 새 과제 근거 / 필수 맥락 누락 → `exception`(사유 보존)
5. 유일 strong이고 반대 근거 없음 → `provisional`. 단 **중요 필드(날짜·금액·담당·결정)에 카드↔전사 불일치가 있으면 `exception`**(내용 검증은 §4 다음 조각까지는 "미확인 표시"로만)
6. 나머지: 중요 업무 의미 있음 AND (귀속 약함/미정 OR 중요 내용 미확인) → `exception`, 아니면 `candidate`
7. **weak + 같은 날 메일 제목·발신자 일치 → 승격 금지**(검색 단서로 refs에만 기록)

위험 표지: 단어 목록은 씨앗. v1에서는 회신 08 §3의 7범주 중 "요청·기한·취소·금지" 표현(~까지, 보내 주세요, 하지 마세요, 아직 미완료)을 정규식으로 추가하고, 의미 해석(조건·인용·부정 극성)은 v2로.

정책 문서: 상태 모델 표(114행)와 09-20 절 2항을 같은 변경에서 v1 문장으로 맞춘다.

## 3. 학습 고리 — "답하면 질문이 줄어드는" 실제 경로

**전제(코드로 확인함).** 카드의 strong/weak는 카드 생성기가 **과제 색인**(retriever)에서 찾은 근거 행으로 정한다: 고유 단서(`distinctive`)가 있거나, 근거 종류 2개 이상 + 서로 다른 단어/항목 2개 이상이면 strong. 공용 단어 목록(shared-term registry)은 반대로 "과제를 결정하지 못하는 말"의 목록이라 학습 자리가 아니다. 그리고 확정된 음성 구간은 **grant(권한 부여) 항목** `<session>:<segment>`으로 과제 색인 준비(`source_preparation`)에 들어간다. 즉 학습 경로는 이미 이것이다:

```
사람 답("그거 KVDS야") → confirm(원장) → 그 구간을 KVDS 과제의 grant에 추가 → 다음 색인 세대에 포함
→ 그 구간의 고유 단어(사람·장비·장소)가 KVDS 근거 행이 됨 → 다음 카드에서 같은 단어 = strong → 묻지 않음
```

**없는 것 3개(만들 것).**
- (L1) confirm → grant 추가의 자동 연결(지금은 사람이 admission 명령을 따로 침). 기존 admission 절차(음성 편입 시험 c006에서 쓴 것)를 confirm 뒤에 호출.
- (L2) 색인 세대 재생성 주기. 지금은 수동. 야간 lane 뒤에 "확정 구간이 새로 생긴 과제만" 세대 재생성.
- (L3) 답 → confirm의 DM 고리(정책 3항, 계획).

**과잉 일반화 방지(검토 부탁).**
- 확정 구간 하나로 strong이 되는 건 그 구간에 *고유* 단서가 있을 때뿐. 사람 이름·고객사처럼 여러 과제에 걸치는 말은 공용 단어 목록이 걸러 `shared_terms_only`로 내린다(기존 규칙).
- 틀린 답을 나중에 철회(withdraw)하면 grant에서 빠지고 다음 세대에서 사라짐 → 학습 취소. 세대 안의 잔류는 재생성 전까지 남는다(한계).
- Owner 답을 규칙("단어 X = 과제 Y")로 직접 쓰지 않는다. 답은 근거 행을 늘릴 뿐이고, 판정은 언제나 근거 수·고유성으로.

**질문:** 이 경로가 "학습"으로 충분한가. 별도 규칙 학습(단어→과제 표)을 두지 않는 것이 맞는가. 몇 번 확정돼야 strong으로 보는 K를 둘 필요가 있는가, 아니면 근거 행 수 규칙으로 충분한가.
