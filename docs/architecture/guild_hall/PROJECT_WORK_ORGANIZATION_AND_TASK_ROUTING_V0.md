# PROJECT_WORK_ORGANIZATION_AND_TASK_ROUTING_V0

## 목적과 상태

이 문서는 모든 Soulforge 프로젝트에 적용하는 **조직도·업무분장 운영 초안**이다. 사람이 보기 쉬운 프로젝트명으로 스레드를 표시하며, 프로젝트 코드·실제 사람·실제 TASK 내용·런타임 식별자는 별도 private metadata에서만 관리한다. 이 문서는 실제 조직 스레드 생성, 담당 확정, 외부 전송 권한을 만들지 않는다.

## 업무분장 규칙

1. 총괄 CEO/업무운영·팀장이 업무분장표로 먼저 분류한다.
2. 각 업무에는 주관 책임자 한 명만 정한다. 다른 분야는 협업 또는 검토로 기록한다.
3. 책임자는 자기 범위 밖 업무를 수행하지 않고, 사유와 적절한 주관 후보를 붙여 재분류 요청으로 반환한다.
4. 주관이 불명확하거나 후보가 충돌하면 총괄 CEO/업무운영·팀장이 판단한다.
5. 최종 담당 확정, 외부 전송·공개, 구매·지급·결재는 사람 owner의 별도 승인이 있어야 한다.

## TASK 스레드 운영

- **새 TASK**: 새 결과물, 여러 단계의 실행, 독립 검증, 또는 지속 추적이 필요한 업무.
- **기존 TASK 계속**: 같은 결과물·주관·범위 안에서 하는 작은 수정·보완.
- TASK는 주관 책임자 하나 아래에서만 운영하고, 협업·검토자는 그 TASK에 참여한다.
- TASK 상태는 `요청`, `진행중`, `확인대기`, `보류`, `완료`, `취소`로 기록한다.
- TASK 완료는 검증 근거가 있을 때만 기록하며, 완료 TASK는 이력으로 남기되 영구 조직도 구성원으로 취급하지 않는다.

## 수락 기록 최소 형식

`업무 → 주관 책임자 → 협업/검토 → 근거 → 확신도 → TASK 판단`

이 형식은 분장안이다. 사람이 승인하기 전에는 실제 담당 확정이나 새 TASK 생성으로 해석하지 않는다.
