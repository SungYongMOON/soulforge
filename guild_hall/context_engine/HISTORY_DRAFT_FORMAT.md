# 이력 외부 초안 파일 계약 v1

이력 CLI는 모델을 호출하지 않는다. `prepare`는 다시 작성할 칸과 자료·맥락 묶음을 만들고,
외부 작성자(사람 또는 별도 봇)가 초안 JSON을 제공하면 `finalize`가 검사·근거 연결·판본 저장을 한다.
봇 프로필, 기억, 모델 선택, 온도, 추가 질문과 도구 권한은 외부 실행자가 소유한다.

## 순서

1. `history_cli.mjs --prepare --input <자료 JSON> --output-root <기존 private 폴더>`를 실행한다.
   선택 `--display-metadata`로 원제목·이름·원자료 링크 표를, `--rules`로 명시된 규칙 파일을 제공한다.
2. 반환된 준비 manifest와 그 manifest가 가리키는 packet 파일을 외부 작성자가 읽는다.
3. 아래 형식의 초안 파일을 만든다. prepare_id와 packet_id는 준비 결과의 값을 그대로 사용한다.
4. `history_cli.mjs --finalize --input <같은 자료 JSON> --prepared <manifest 파일>
   --draft <초안 JSON> --output-root <같은 폴더>`를 실행한다. 규칙·표시 정보도 같은 것을 사용한다.

하위 초안이 준비된 변경 칸만 전달한다. 일별 칸이 바뀌면 이를 먼저 작성하고,
finalize가 주·월·최근 현황의 갱신 대상 목록을 반환한다. 다음 prepare에서 준비된 위층 자료를 받는다.
위층 내용을 CLI가 대신 쓰거나 빈 초안으로 만들어 채우지 않는다.

## 초안 JSON — 하나의 고정 형식

```json
{
  "schema": "soulforge.history_external_draft.v1",
  "prepare_id": "sha256:<준비 manifest 지문>",
  "drafts": [
    {
      "packet_id": "sha256:<해당 packet 지문>",
      "sentences": [
        {
          "text": "도면을 요청했다.",
          "evidence_ids": ["SOURCE-001"]
        }
      ]
    }
  ]
}
```

- `text`는 이력 문장이다. 날짜에 기록된 일을 짧은 과거 사실로 쓴다.
- 작성자가 명시한 `sentences: []`도 허용한다. 이때 `외부 초안에 문장 없음`과 미사용 근거를 표시하며,
  원천 자료가 없었다거나 모든 내용을 검토했다는 뜻으로 취급하지 않는다.
- `evidence_ids`는 그 packet 안에서 허용된 근거 번호다. 일별 초안은 원천 번호,
  위층 초안은 하위 이력 번호를 사용한다. 다른 packet·날짜·과제의 번호를 빌리지 않는다.
- 일별 배치를 JSON 부분 추출과 1회 재호출 후에도 읽지 못하면, 해당 문장을 만들지 않고
  일별 draft 항목에 선택 `unprocessed_batches`를 넣는다. 각 항목은
  `{"batch_index": 1, "reason": "format_invalid_after_retry"}` 형식이며,
  출처 번호 불일치는 `source_link_invalid_after_retry`를 쓴다. finalize가 묶음 번호를
  검증하고 보는 판에 미처리로 표시한다. 나머지 묶음의 문장은 그대로 제출한다.
- 인용문·파일명·원자료 경로·발화 시각을 작성자가 새로 만들지 않는다. 코드가 번호로 연결한다.
- 질문을 확정 사실로, 제안·계획을 완료로, 조건문을 무조건적인 결과로 바꾸지 않는다.
  인명·전문용어를 추측하여 고치거나 숫자·단위·부정·범위를 바꾸지 않는다.
- 남은 일·중요도·확인할 결과·후속 요청이 남아 있다는 판단을 덧붙이지 않는다.
  요청은 누가 무엇을 요청했다는 사실로만 적는다.
- 주·월 초안은 같은 사건을 묶어 5~10줄로 압축하고, 최근 현황은 최근 있었던 일만 정리한다.
- 주·월·최근 현황 draft 항목에는 선택 `merge_fallback: true`를 둘 수 있다. 한도를 넘어 부분으로 나눠 쓴 요약의 합치기가 실패해
  부분 문장을 그대로 제출했다는 표시이며, 보는 판에 `… 요약 합치기 실패 — 부분 요약을 그대로 사용`으로 보인다.
- 주·월 draft 항목에는 선택 `upper_fallback: true`를 둘 수 있다(최근 현황·일별은 거부). 작성자 답이 같은 입력으로 거듭 거부되어
  하위 카드 문장을 카드 하나당 한 문장·그 카드 번호 하나로 그대로 제출했다는 표시이며, 보는 판에
  `… 요약 작성이 거듭 거부됨 — 하위 기록 문장을 그대로 사용`으로 보인다. 압축 요약이 아니다.
- 이 JSON은 검토 전 외부 초안이다. 작성자가 사람이라고 해도 Owner 수락이나 정본 승격을 뜻하지 않는다.

## 검사와 판본

준비 묶음에는 과제·기간·입력 지문·규칙 지문·현재 head 지문과 허용 근거가 묶인다.
finalize는 초안 전체를 먼저 검사하며, 허용하지 않은 번호·다른 준비 묶음·오래된 head·바뀐 입력이나 규칙은 거부한다.
같은 준비 묶음의 형제 칸들은 한 번의 head 갱신으로 저장한다. 일부만 검사하고 현재 판을 전진시키지 않는다.

같은 입력과 규칙의 이미 작성된 칸은 다시 요청하지 않는다. 동일 초안의 재제출은 무변경이며,
기존 불변 cell·head·화면 판은 덮어쓰지 않는다. 변경된 위층은 과거 판으로 보존하고 현행으로 표시하지 않는다.
쓰지 않은 근거는 집계하여 보여 준다. 일부 문장만 넣은 흐름 시험을 전체 자료를 빠짐없이 정리한 결과로 보고하지 않는다.
finalize는 일별 입력 자료 중 어떤 문장에도 인용되지 않은 자료 수와 전체 자료 수를
코드로 계산해 결과 요약과 보는 판 맨 아래에 함께 표시한다. 인용되지 않은 음성 구간 중 카드 성격이 업무가 아닌 것
(`project_work`·`team_operations` 밖)은 `unquoted_non_work_voice`로 따로 세어 `(그중 업무 외 녹음 구간 n)`으로 보인다.
일별 결과가 공용 입력 한도를 넘으면 근거 카드를 불변 묶음 파일로 나눠 저장하고,
읽을 때 각 묶음의 지문을 확인해 보는 판에서 순서대로 합친다. 공용 한도는 변경하지 않는다.
원천 입력이 처음부터 비어 있으면 요청할 packet이 없으며, 기존 이력이 있는 상태의 빈 원천 입력으로 현행 판을 지우지는 않는다.

형식·번호·범위·지문 검사는 문장의 의미가 맞다는 검증이 아니다.
결과의 기본 표시는 `외부 초안 · 의미 검증/사람 수락 전`이며,
PLAUD 원제목·녹음 시각·발화 번호/구간·원자료 링크와 미확인·후보 귀속 표시를 유지한다.
음성 자료 하나는 대화 구간 하나다(입력 형식 v3, KST 날짜가 바뀌면 날짜별로 나뉜다). 그 구간의 발화가 줄마다 들어 있고,
작성자에게는 구간 제목(길잡이일 뿐 근거가 아님)·성격·KST 시각 범위가 함께 보인다. 작성자는 구간마다 한 문단으로 사실만 쓰고
그 source_id 하나를 근거로 댄다. 발화 번호·시각은 코드가 붙인다.
음성 근거 줄은 `PLAUD · 녹음 원제목 · 날짜 시작–끝 · 발화 a–b(n개) · 전사 출처 · [녹음] · [전사] · (귀속 표시) · 발화자 미확인` 한 줄이다.
Linear 근거 줄은 `날짜 · Linear · 작성자 이름 · 작업 제목 · 담당 이름 · 상태`이며 계정 ID를 보이지 않는다(이름이 없으면
`작성자 미기록`). 첨부가 있을 때만 첨부를 붙인다. Slack에서 이름을 모르는 사용자 ID는 `작성자 미확인`으로 보인다.
음성 근거 줄에는 카드가 읽은 전사(`PLAUD 전사`/`자체 전사`/`자체 전사(PLAUD 없음)`/`자체 전사(PLAUD 사용 불가)`/`전사 출처 미상`)를 코드가 붙인다(표시 전용).
같은 날 서면 자료 일치로만 들어온 음성은 근거 줄에 `(귀속 약함)`이 붙는다. 작성자는 이를 확정 귀속으로 쓰지 않는다.
보는 판은 같은 칸에서 근거 번호 집합이 똑같은 문장을 한 문단(최대 6문장·600자)으로 묶어 근거 줄을 한 번 보인다.
초안의 문장 단위·저장 cell·지문은 바뀌지 않으므로 작성자는 문단 묶기를 위해 문장을 합치지 않는다.
첨부 표시에서 수집기의 `body_inline_image` 표시가 있는 본문 삽입 이미지만 제외한다.
파일명 모양으로 첨부를 제외하지 않는다.

직접 모델 호출, Hermes 실행, 네트워크 전송, 봇 등록, 예약 작업은 두 명령의 기능이 아니다.
